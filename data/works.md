# Реестр трудов (`data/works.json`) и «Полка» (`data/shelf.json`)

Два файла данных, из которых сборка рисует всю базу нот. Руками карточки со ссылками на
файлы в `src/` не пишут.

- `data/works.json` — записи, чей файл лежит у нас в `files/`. Сборка копирует `files/` в
  сборку как есть, рисует блок «Файлы для скачивания» на «Трудах» и ставит ссылку на PDF
  в строку концерта (поле `number`).
- `data/shelf.json` — всё остальное: карточки полок на «Трудах» и обе таблицы «Полки»
  (`shelf.html`, `en/shelf.html`). Внешнее даётся только ссылкой; чужих файлов в `files/` нет.

Правило владельца 27.11.2026: публикуется то, что в открытом доступе, — с указанием источника
на сайте. Скан издания из открытой библиотеки становится файлом после сверки издания.

## Поля записи `works.json`

| Поле | Обязательное | Что это |
|---|---|---|
| `id` | да | латинский slug (`[a-z0-9-]+`), уникальный |
| `title` / `title_en` | `title` | название по-русски / по-английски |
| `type` | да | `concert`, `school`, `etudes`, `ensemble`, `arrangement` |
| `number` | нет | номер концерта: ставит ссылку на PDF в строку таблицы концертов |
| `instrument` | нет | «тромбон», «туба» |
| `year` | нет | только год из источника; не известен — пустая строка, не выдумывать |
| `edition` / `edition_en` | нет | издание по титульному листу или карточке источника |
| `pages` | нет | число страниц PDF |
| `notes_url` | нет | партитура, путь от корня сайта (`files/…`) |
| `sha256` | да, если есть `notes_url` | сборка сверяет с файлом и падает при расхождении |
| `source_title` | да, если есть файл | источник на сайте: «IMSLP · Российская государственная библиотека», «Архив проекта» |
| `source_url` | нет | `https://…` — источник становится ссылкой; пусто для «Архива проекта» |
| `origin` / `origin_en` | да, если есть файл | как файл попал в проект |
| `comment` / `comment_en` | нет | пояснение для карточки |

## Поля записи `shelf.json`

| Поле | Обязательное | Что это |
|---|---|---|
| `id` | да | slug, уникальный и не совпадающий с `works.json` |
| `shelf` | да | `schools`, `etudes`, `ensembles`, `studies` — полка на «Трудах» |
| `instrument` / `instrument_en`, `tag` / `tag_en`, `description` / `description_en`, `title` / `title_en` | да | текст карточки RU / EN |
| `edition` / `edition_en`, `rights` / `rights_en` | да, если запись показывается на «Полке» | издание и статус прав |
| `url` + `url_title` / `url_title_en` | нет | внешняя ссылка (`https://`) и её подпись |
| `file` | нет | `id` записи `works.json`: карточка ведёт на свой PDF |

Запись без `url` и `file` остаётся карточкой на «Трудах», но на «Полке» не показывается.

## Правила

- Файл, на который указывает `notes_url`, обязан лежать в `files/`; в `files/` не должно быть
  файлов вне реестра — `tools/test_v3.py` сверяет оба множества.
- У каждого файла назван источник (`source_title`); записи «неизвестно» не бывает.
- Даты изданий не унифицировать без основания; разночтения источников сохранять (AGENTS.md).
- Статусы сложности не выдумывать: все записи «не оценено по нотам».
- Чужие по правам издания (Robert King, IMC, авторский текст 2020 года) — только ссылкой.
- Записи (MP3) возвращаются в тот же реестр и `files/`; с 27.11.2026 записи на сайте нет.

## Как добавить файл

1. Сверить издание по титульному листу; для скана из открытой библиотеки — сверить размер и
   число страниц с карточкой источника.
2. Положить PDF в `files/` (латиницей, без пробелов), посчитать `sha256sum`.
3. Добавить запись в `works.json` и, если нужна карточка, в `shelf.json`.
4. `python build.py …`, `tools/check_site.py`, `tools/test_v3.py` — зелёные.
