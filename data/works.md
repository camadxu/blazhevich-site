# Реестр трудов (`data/works.json`)

Локальная база проекта (этап 1, PLAN §4): записи о произведениях и их файлах.
`build.py` читает реестр при сборке: валидирует его и рисует блок «Файлы для скачивания»
на странице «Труды». Схема меняется только вместе с `build.py`.

## Поля записи

| Поле | Обязательное | Что это |
|---|---|---|
| `id` | да | латинский slug (`[a-z0-9-]+`), уникальный |
| `title` / `title_en` | `title` | название по-русски / по-английски |
| `type` | да | `concert`, `school`, `etudes`, `ensemble`, `arrangement` |
| `year` | нет | только год из источника; не известен — пустая строка, не выдумывать |
| `edition` | нет | издание по источнику (номер опуса, издательство); пусто, если не проверено |
| `notes_url` | нет | партитура, путь от корня сайта (`files/…`) |
| `parts_url` | нет | партии (путь или список путей); пусто, пока партий нет |
| `audio_url` | нет | аудиозапись |
| `origin` / `origin_en` | да, если есть хоть один файл | происхождение файла — откуда он взят; не оставлять «неизвестно» |
| `comment` / `comment_en` | нет | пояснение для карточки |

## Правила

- Файл, на который указывает `*_url`, обязан лежать в `files/` — сборка падает иначе.
- Даты изданий не унифицировать без основания; разночтения источников сохранять (AGENTS.md).
- Статусы сложности не выдумывать: сейчас все записи «не оценено по нотам».
- Чужие нотные файлы в `files/` не размещать — только файлы с подтверждённым происхождением.
