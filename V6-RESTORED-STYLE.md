## 2. Первый экран

1. Сконвертировать `assets/hero-home-restored.png` → `assets/hero-home.webp` (замена): полноэкранная версия 2880×1568, Pillow/WebP, качество 78–84; если файл больше ~600 KB — уменьшить до 2560 или 2400 по ширине. Текущий файл 1306×816 / 122 KB — новый должен остаться «лёгким» для LCP: цель ≤ 450 KB, решение зафиксировать в описании коммита.
2. Мобильный вариант (если в разметке/медиа-правилах используется отдельный файл или `srcset`): кроп 1080–1280 по ширине с кадрированием по центру композиции — лицо и раструб в кадре, `object-position` при необходимости.
3. Проверить cover-кадрирование на 360 / 430 / 768 / 1024 / 1440 / 1920: лицо не режется, Большой театр читается, низ растворяется в бумагу без полосы.
4. `assets/og-image.jpg` пересобрать из нового hero (1200×630) в том же тоне.
5. `theme-color`, favicon, страница 404 — сверить с новой бумагой (они уже в светлой гамме; после замены hero не должны расходиться).
6. При наведении на `.hero-mark` и любые элементы первого экрана не должно появляться всплывающих плашек: на проде 15.11.2026 у руки была видна плашка «Blazhevich — Bra…». Найти источник (обычно `title`-атрибут ссылки) и убрать; проверять без «МЕНЮ»-кнопки на первом экране — её владелец убрал 13.11.2026, не возвращать.

## 3. Единая обработка всех фотографий

Одна тоновая кривая на все документальные фото (как в V5), приведённая к эталону: ориентир — тёмный `#47321d`, светлый `#f2e7cf`, гамма ≈ 0.85; зерно и виньетка у краёв — единые на всю систему. Точные значения подобрать по замерам из §1 и зафиксировать в описании коммита (детерминизм сборки важнее идеала).

Список файлов в `assets/`:

- `blazhevich-1903.webp` + `blazhevich-1903-560.webp` — портрет 1903 года (колонка в главе 1900–1905);
- `bolshoi-1905.webp`, `conservatory-1940s.webp` — архивные снимки в биографии (`.ch-plate`);
- `v-bolshoi-colonnade.webp`, `v-conservatory-portico.webp` — виды-подложки;
- `scene-moscow.webp` + `scene-moscow-960.webp`, `scene-leningrad.webp` + `scene-leningrad-960.webp` — шапки досье.

Правила:

- Техническое улучшение — детерминированно, Pillow: при необходимости апскейл ×2 (Lanczos), лёгкий unsharp mask, сведение к единой кривой. **Содержание не менять**: лица, здания, вывески, рукописные тексты — как есть; никакой ИИ-дорисовки документальных фото.
- Глубокая реставрация/апскейл отдельных снимков (как hero) — только через конвейер владельца: запросить готовый файл у владельца, в репо класть только результат. Самостоятельно генеративные модели для документальных фото не применять.
- `autograph-1903.webp` — **не трогать** (автограф в московской шапке вырезан из макета владельца, AGENTS.md).
- После обновления исходников перегенерировать шапки досье скриптами `tools/scenes/moscow_scene.py` и `tools/scenes/leningrad_scene.py` — они режут и тонируют под бумагу; следить, чтобы их параметры соответствовали новой кривой.

## 4. CSS, типографика, компоненты

- Сверить все токены `src/style.css` (`:root`) с эталоном: `--paper:#e8dbbf` не менять; `--ink`, `--gold`, `--rule`, `--surface`, `--band`, `--select`, `--field` — проверить на посторонние оттенки и контраст (текст ≥ 4.5:1 к бумаге). Остатки любых не-сепийных цветов (например, старый имперский синий v5) — заменить на умбру/золото из палитры.
- Зерно `--grain`: интенсивность согласовать с естественным зерном эталона, чтобы CSS-шум не спорил с фотографией.
- Структуру и типографику не менять: серифные заголовки, золотые годы и номера 01–07 (`deco()` в `build.py`), буквица биографии, пластинки `.records`, дерево `ol.lineage`, таблицы концертов. Только тон: цвета, тени (`color-mix` от `--ink` 14%), рамки.
- Шапки досье и подвал — в ту же бумагу и кривую; проверять стыки «фото → бумага».

## 6. Порядок работы

1. Ветка от `main` в форке `camadxy/blazhevich-site`, имя `v6-restored-style`.
2. Шаг 1: токены CSS + замена hero + og-image → сборка → визуальная проверка первого экрана.

4. Шаг 3: проход по разделам и досье (§7), правки тона по месту.
5. Проверки, все три без ошибок:
   ```sh
   python build.py
   python tools/check_site.py
   python tools/test_v3.py --release --domain https://blazhevich.tech --lastmod ГГГГ-ММ-ДД
   ```
   (`--lastmod` — дата содержательной правки; повторная сборка обязана совпасть байт-в-байт).
6. Коммит с описанием параметров кривой и весов файлов, push в ветку форка. Владелец вливает в `main` `camadxu/blazhevich-site`, CI обновляет тест-сайт; после приёмки владельцем — запись об изменении по образцу записей 13.11.2026 в AGENTS.md. Прод публикует только владелец.
