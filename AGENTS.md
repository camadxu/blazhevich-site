# AGENTS.md — правила для ИИ-агентов (сайт Блажевича)

## Что это за проект

Статический сайт о Владиславе Блажевиче (1881–1942), тромбонисте и педагоге. Русская и английская версии, каталог нот с поиском и фильтрами. Собирается `build.py` из `src/` (Python 3, только стандартная библиотека).

- **Прод:** https://blazhevich.tech — обновляется ТОЛЬКО владельцем вручную (workflow «ПРОДАКШЕН: публикация deploy/prod» в GitHub Actions).
- **Тест:** https://test.blazhevich.tech — после каждого push в `main` репозитория `camadxu/blazhevich-site` CI сам пересобирает ветку `deploy/test`, и хостинг забирает её сам по вебхуку (автодеплой работает, по отчёту владельца от 12.11.2026); кнопка Deploy в hPanel остаётся запасным способом. Тестовая версия — черновая сборка: `noindex,nofollow` + плашка «не опубликовано». Это норма, а не дефект: тест-сайт не должен индексироваться поисковиками.

## Безопасность — абсолютные запреты (установлены владельцем)

- Никогда не запрашивай, не принимай и не используй: пароль Hostinger, FTP-пароль, SSH-пароль, доступ к файловому менеджеру hPanel с правом записи, полный доступ к аккаунту хостинга.
- Всё, что требует доступов к хостингу (создать Git-конфиг в hPanel, добавить deploy-ключ, настроить вебхук, залить файлы вручную), делает владелец лично. Твоя роль — подготовить изменения и дать владельцу готовые шаги.
- Не добавляй в репозиторий и не запрашивай никакие секреты. Схема деплоя не требует секретов: хостинг сам забирает код по read-only deploy-ключу, который владелец добавляет в GitHub вручную.
- Не пушь в ветки `deploy/*` вручную — их пишет только CI.

## Обычный цикл работы

1. Вноси изменения в `src/` и `assets/`. **Не редактируй `site/` руками** — он полностью генерируется `build.py`.
2. Локально проверь:
   ```
   python build.py
   python tools/check_site.py
   python tools/test_v3.py
   ```
   Все три команды обязаны пройти без ошибок. `test_v3.py` нужно запускать сразу после сборки с теми же аргументами `--release/--domain/--lastmod` (или задать их через `BLZ_DOMAIN`/`BLZ_LASTMOD`) — он проверяет воспроизводимость пересборкой.
3. Коммит в рабочую ветку и push в форк `camadxy/blazhevich-site` (рабочий стол ИИ-сессий, на нём нет CI и `deploy/test`). Владелец вливает ветку в `main` репозитория `camadxu/blazhevich-site`, CI собирает `deploy/test`, хостинг выкладывает её на тест-сайт автоматически.
4. Владелец смотрит тест-сайт. Публикация в прод — только владелец запускает workflow «ПРОДАКШЕН: публикация deploy/prod».
5. В `main` репозитория `camadxu` агенты напрямую не пушат: только ветка в форке, вливает владелец. Хостинг, CI, вебхуки и deploy-ключи живут только в `camadxu/blazhevich-site`; подключение hPanel не трогать.
6. `TEST-RESULTS.json` генерируется `test_v3.py`, в репозиторий не входит.

## Команды сборки

- Черновик (для теста): `python build.py`
- Публичная (для прода): `python build.py --release --domain https://blazhevich.tech --lastmod ГГГГ-ММ-ДД`
- `--lastmod` — дата содержательной редакции, а не случайное число (см. V3-START-HERE.md).
- Сборка детерминированна: повторный запуск с теми же аргументами даёт байт-в-байт тот же результат (в том числе на Windows — сборщик принудительно пишет LF).

## Контент-дисциплина

- Факты — только из источников; сохранять происхождение фактов; разночтения источников не сглаживать без проверки; даты изданий не унифицировать без основания.
- Статусы сложности нот не выдумывать: сейчас все записи «не оценено по нотам».
- Написание бренда: владелец менял его с «Blszhecich» на «Blazhevich» — использовать Blazhevich.
- В исторических документах (README.md, HANDOFF.md) фигурирует домен blazhevich.space — это прошлое имя проекта; актуальный домен: blazhevich.tech. Исторические документы не переписывать, пометка актуальности — в этом файле и в DEPLOY.md.
