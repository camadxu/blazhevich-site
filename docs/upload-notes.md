# Публикация нот: от скана до прода — цикл для агента

Сквозной процесс добавления нот в базу сайта. Схема данных и поля записей — `data/works.md`;
правила прав и контента — `docs/LIBRARY.md`; цикл репозитория, сборка и запреты — `AGENTS.md`;
хостинг и публикация — `docs/DEPLOY.md`; очередь пробелов базы —
`docs/research/2026-11-27-score-gaps.md`.

## Права и источники

Основание — решение владельца 27.11.2026 (`AGENTS.md`): Блажевич умер 10 апреля 1942 года, его
музыка — общественное достояние; публикуется то, что в открытом доступе, с указанием источника
на сайте. Фильтр «что перед глазами → куда идёт»:

| Что перед глазами | Куда идёт |
|---|---|
| Свой скан или файл из архива проекта | файл в `files/`; `source_title` «Архив проекта», `source_url` пусто |
| Скан из открытой библиотеки (IMSLP, tubastas.ru) | файл после сверки издания (шаг 3); до сверки — карточка со ссылкой в `data/shelf.json` |
| Чужие права на оформление или текст (Robert King, IMC, авторский текст 2020 года) | карточка со ссылкой в `data/shelf.json`; файла в `files/` нет |

Издание с живым копирайтом на оформление или текст (переложения, редакции, авторские эссе)
получает карточку со ссылкой — как «Концертные дуэты» (IMC) в `data/shelf.json`. Существующие
исключения (переложение Cofield, «Школа» без титульного листа) перечислены в
`docs/LIBRARY.md`; каждое новое исключение — отдельное решение владельца.

## 1. Клон

Клоны держать на `C:` (диск `D:` повреждён), git по https. Одна сессия — один клон;
параллельные агенты — каждый в своём.

```
git clone https://github.com/camadxu/blazhevich-site.git <папка-на-C:>
cd <папка> && git switch -c <рабочая-ветка>
```

Перед началом `git fetch` и сверить `HEAD` с `origin/main`. Если clone, push или `gh` молча
висят — снять прокси-переменные среды: в окружении бывает мёртвый локальный прокси
(например `socks5h://127.0.0.1:11090`).

Готово, когда `git status --short` пуст и `git rev-parse HEAD` равен `git rev-parse origin/main`.

## 3. Сверить издание, положить файл

- Титульный лист против карточки источника: издатель, год, состав. Для скана из открытой
  библиотеки — размер (байты) и число страниц против карточки.
- Совпадает → имя `blazhevich-<работа>-<состав>-<год>.pdf` (латиница, без пробелов; образцы —
  имена в `files/`), файл в `files/`, `sha256sum files/<имя>.pdf`.
- Издание расходится или не установлено → файл в `files/` не кладётся: карточка со ссылкой
  на источник в `data/shelf.json` (таблица выше), работа продолжается с шага 7 без файла.

Готово, когда файл в `files/` и его хэш посчитан.

## 4. Запись в `data/works.json`

При файле обязательны `sha256` (из шага 3), `source_title`, `origin` (+`origin_en`). Тексты —
парами RU/EN. Концерту ставится `number`: по нему сборка вставляет чип «PDF, N стр.» в строку
таблицы концертов (`link_concertos()` в `build.py`); строки с таким номером нет — сборка падает.
Поля и их условия — таблица в `data/works.md`; образец — запись `concerto-2`.

Готово, когда JSON читается
(`python -c "import json; json.load(open('data/works.json', encoding='utf-8'))"`)
и обязательные поля на месте.

## 5. Карточка в `data/shelf.json` (когда нужна)

`file` = `id` записи из `works.json`; тексты тоже RU/EN; образец — `sequences-own`. Запись без
`url` и `file` остаётся карточкой на «Трудах» и на «Полке» не показывается.

Готово, когда `file` указывает на существующий `id` из `works.json`.

## 6. Проверки

Три команды сразу после сборки, с той же датой в `--lastmod`/`BLZ_LASTMOD` (правила сборки —

```
python -X utf8 tools/check_site.py
BLZ_DOMAIN=https://blazhevich.tech BLZ_LASTMOD=ГГГГ-ММ-ДД python -X utf8 tools/test_v3.py
```

На этой машине лаунчера `py` нет — использовать полный путь к интерпретатору
`C:\Users\IAI\AppData\Local\Programs\Python\Python312\python.exe`.

Готово, когда все три команды прошли без ошибок.

## 7. Ветка, push, PR

Коммит в рабочую ветку из шага 1, `git push -u origin <ветка>` (ошибка «remote rejected …
commit_refs_rules» бывает транзиентной — повторить пуш), затем `gh pr create` в `main`.
В `main` напрямую не пушить; вливает владелец. После влива CI пересобирает `deploy/test`, и
хостинг сама выкладывает его на test.blazhevich.tech. Коммит только с `.md` CI не запускает
(`paths-ignore: **.md` в `.github/workflows/deploy-test.yml`) — правки документации на
тест-сайт не попадают, и это норма. Ветки `deploy/*` пишет CI; руками туда не пушить.

Готово, когда PR открыт; для правок с файлами (не только `.md`) `gh pr checks` должен стать
зелёным после влива — на самом PR CI не запускается.

## 8. Тест и прод

- Тест: для правок контента test.blazhevich.tech обновляется сам после влива.
- Прод — только владелец: Actions → «ПРОДАКШЕН: публикация deploy/prod» → Run workflow →
  кнопка Deploy в hPanel. hPanel открывается во встроенном браузере ZCode через реле
  Манчестер (`~/.agents/docs/zcode-browser-proxy.md`); доступов к хостингу не запрашивать
  (`AGENTS.md`).

## Живая проверка

До прода — test.blazhevich.tech, после запуска прода — blazhevich.tech:

- `works.html` и `en/works.html`: блок «Файлы для скачивания» со своей строкой и источником;
  для концерта — чип «PDF, N стр.» в строке таблицы с его номером;
- `shelf.html` и `en/shelf.html`: карточка со ссылкой «Открыть PDF»;
- `/files/<имя>.pdf` отвечает HTTP 200, `sha256sum` скачанного совпадает с реестром.
